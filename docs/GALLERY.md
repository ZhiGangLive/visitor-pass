## 三、视频号图文

**用图**：`docs/gallery/vertical/` 下 9 张

```
01-hook → 02-approval → 04-form → 05-card → 09-pass
→ 10-ledger → 11-verify-only → 12-lightweight → 13-closing
```

**标题**

```
不是审批，是邀请：一套可离线运行的访客系统
```

**描述**

```
访客管理的默认设计是「审批」：访客申请、员工点通过、保安在门口盘问。
这条链路里，发起权在访客，判断权在保安，唯一该负责的邀请人反而不在场。

我们把它改成了「邀请」：员工填四个字段生成邀请卡，微信直接转发；
访客零安装；门岗单输入框核验，2 秒放行；台账自动生成，可导出 CSV。

工程上做了三条取舍：
一是零 npm 依赖，Node 16+ 双击即跑，客户不需要运维；
二是单文件 JSON 存储，原子写 + 每日备份 + 坏文件隔离；
三是断网可用，适配内网与涉密场景。

代码开源（AGPL-3.0），仓库见评论区。
```

**发布设置**
- 视频号图文偏稳重，描述可以长一点，前两行是摘要
- 第 1 张建议用 `01-hook`，比 `13-closing` 更能留住人

## 五、通用提示

**图上已经有字，正文别再复述。**
比如第 4 张写着「填四个字段」，正文就该讲「为什么只要四个字段」，而不是再数一遍。

**顺序就是叙事。**
`01 → 02 → 03` 是「提问 → 现状 → 反转」，这三张不要拆开或调序，它是整组的钩子。

**封面只选一张。**
小红书用 `01-hook`（3:4），抖音用 `01-hook`（9:16）。
`13-closing` 适合当最后一张，不适合当封面——它没有信息量，只有情绪。

**不要给图加平台水印。**
同一套图要在三个平台复用，带水印就得重做。
